## 変更

- 月初から予測日前日までの公式 RaceList → DebaTable → RaceMarkTable を取得。
- 馬名・生年月日・父・母の厳密識別を維持。公式馬ID・馬番・馬名も結果と照合。
- 完全な着順・頭数・時計が揃うレースだけ追加。取消・中止・同着などは保留。
- 元ページ・取得時刻・SHA256・採用件数・保留理由を保存。全日程を網羅したと偽らない。
- 同日・未来の成績、重複や既存月次データとの不一致は取り込まない。
- 新馬などは「未出走」、古い履歴や未収録は「履歴不足」、同名別識別は「照合不一致」。評価不能馬を50点で順位付けしない。
- 採点項目・配点は変更しない。人気・オッズは採点に使わない。自動購入なし。

## ローカルで使用

```bash
python nar_history.py --input . --output data/processed
python nar_current_history.py --as-of 2026-10-26
python nar_cloud_prerace.py --history data/processed/horse_history_current.csv --minutes 1
```

最後のコマンドは実行当日だけの動作確認。過去日の事前評価として保存し直さない。
日付を省略すると日本時間の今日。指定したas-of当日の成績も除外する。
取得した履歴は今取得した公式結果であり、過去時点で利用できたことを証明する履歴ではない。
厳密な過去の時系列バックテストでは、その時点に保存された履歴スナップショットを別途使用する。

## GitHub Actions

nar-current-history.yml は手動実行・再利用ワークフロー。nar-prerace-cloud.yml から前処理として呼び出す。
キャッシュで同じ元ページの再取得を減らす。各元ページのハッシュを読み込み時に検証する。
取得済みページは再取得しないため、後日の公式訂正を反映するには該当キャッシュを無効化して再取得する。
初回は最大90分の補完前処理があり、収集開始が遅れる可能性がある。補完が失敗しても既存月次履歴で監視を開始し、Summaryに記録する。
1分の手動インストール確認は当月収集を省略して既存履歴を使用する。
履歴成果物の current_results/manifest.json で採用件数・未確認日・保留レースを確認する。
履歴の最終収録日は各事前評価のrun_manifest.jsonに保存される。

## 適用

この環境からGitHubへの反映は行っていない。既知の書き込み403設定確認は繰り返さない。
Codespacesで experimental-v3-20261023 に切り替え、未コミット変更がない状態で、同梱パッチを適用する。

```bash
git apply --check current-history-20261026.patch
git apply current-history-20261026.patch
python -m unittest discover -s tests -q
```

テスト後に変更をコミットして experimental-v3-20261023 にpushする。
その後mainにも以下の2ファイルを同じ内容で登録する（呼び出されるワークフローがmainにも必要）。
- .github/workflows/nar-current-history.yml
- .github/workflows/nar-prerace-cloud.yml

コードはexperimentalブランチからcheckoutする既存構成を維持している。
